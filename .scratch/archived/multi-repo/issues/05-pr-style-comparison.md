## Comportement

- La sélection s'écrit **source → fusionnée dans → destination** (comme à la création d'une PR) ; la plage relue est `destination...source`.
- Sans configuration : source = working tree, destination = `main` (ou la branche par défaut du dépôt si `main` n'existe pas).
- « Définir par défaut » enregistre source et destination dans `.relief/settings.json` (cas d'usage `Session::settings`), relus à l'ouverture ; une plage passée en argument (`relief . A...B`) prime.

- [ ] Cas d'usage : défauts sans fichier ; défauts relus après réouverture ; argument prioritaire.
- [ ] e2e acme-shop : source et destination affichées, changer la source change la carte, « par défaut » survit au rechargement.

## Answer

- Cœur : `Settings { source, destination }` (modèle + contrat JSON), `Session::settings()` / `set_settings()` dans `<données>/settings.json`. Défauts : source = working tree, destination = `main`, sinon la branche courante, sinon `HEAD`. Une plage passée à l'ouverture prime et n'écrase pas le fichier. Commandes Tauri `settings` / `set_settings`.
- UI : le sélecteur s'écrit source → « fusionnée dans » → destination, plus « Définir par défaut » ; la plage relue est `destination...source` (ou `destination` seul avec le working tree). Décision : le bouton deux/trois points disparaît ; l'inversion et le compteur de commits restent. Sans plage à l'ouverture, l'UI part des réglages.
- Harnais e2e : `// @no-range` en 2e ligne d'une spec acme-shop lance l'app sans plage.
- Vérifié : cargo 694/0, web 1066/0, e2e 185 passés / 1 ignoré, lint propre, captures EN/FR relues.
