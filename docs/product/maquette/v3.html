U23 · maquette

Base / head : lire le sens de la comparaison

Le contrôle base ··· head ⇄ de U19 permet de choisir les deux côtés, mais rien ne dit lequel est la référence, ni que la carte montre ce que head change par rapport à base. En mode ..., la vraie base est l'ancêtre commun, qui n'apparaît nulle part. Deux options, une recommandation ; rien n'est implémenté.

Option A · recommandée

Rôles écrits sur le contrôle, flèche, ligne de lecture

  • Chaque côté porte son rôle au-dessus de la ref : Référence (base, gris) et Changements (head, couleur d'accent, souligné). Le head est le côté « actif » : c'est lui qu'on relit.
  • ··· devient une flèche → (lecture base → head) ; un clic bascule toujours ... / .., l'infobulle dit lequel.
  • Sous la barre, une ligne de lecture : « La carte montre ce que develop change par rapport à main, depuis leur ancêtre commun 4e1a9c2 ». Elle disparaît après 5 s ou au premier clic sur la carte, et revient au survol du contrôle.
  • ⇄ reste, désactivé quand head est le working tree (on ne compare pas un commit « par-dessus » le working tree).
  • + garde la place de U19, change peu de code (libellés, flèche, une ligne).
  • − deux lignes de texte dans la barre : un peu plus haute (36 → 40 px).
Option B

Une phrase : « Changements de [head] par rapport à [base] »

  • Le contrôle se lit comme une phrase, head en premier : c'est ce qu'on relit.
  • Le mode ... / .. devient un lien en fin de phrase : « depuis l'ancêtre commun » / « diff direct ».
  • + impossible de se tromper de sens.
  • − long (≈ 420 px), mal adapté à 1024 px avec la recherche ; l'ordre head, base est l'inverse de git (main...develop).
Cas particuliers (les deux options)
  • Working tree : head affiche « Working tree » avec la mention « non commité, index compris » ; la base par défaut est HEAD. La ligne de lecture dit « ce que vos modifications non commitées changent par rapport à HEAD (a7c03f1) ».
  • Ancêtre commun (...) : la ligne nomme le sha court du merge-base, et le menu de base le montre aussi (marque BASE sur le rail de l'onglet Commits, déjà là depuis U19).
  • Diff direct (..) : « … par rapport à main tel quel (diff direct) » ; ce que main a reçu depuis apparaît aussi, en sens inverse.
  • Pas d'ancêtre commun : la ligne passe en avertissement et le mode bascule en diff direct.
Ce qu'il faut côté cœur
  • Le sha de la base réellement utilisée (merge-base en ..., base telle quelle en .., HEAD pour le working tree) : aucun champ public ne l'expose aujourd'hui. Il faut un champ base_resolved (sha court) dans DiffResponse, et le contrat TS régénéré.
  • Rien d'autre : la plage reste la chaîne base...head.
